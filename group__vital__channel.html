sapi_status_t sapi_vital_channel_init ( sapi_vital_channel_t *  storage,
const sapi_vital_channel_config_t *  config,
void **  channels,
uint32_t  channel_count 
)

Initialize a vital (redundant) channel with voting logic.

Initializes a pre-allocated vital channel that wraps multiple underlying channels (IPC or other transport) and performs voting-based arbitration on all sends and receives.

The caller must configure backend_send and backend_recv callbacks in the config to specify how to invoke transport-specific operations. This design allows vital_channel to remain transport-agnostic (works with IPC, shared memory, TCP, or any other mechanism).

Parameters
[out]storagePre-allocated storage for the vital channel (must not be NULL)
[in]configChannel configuration with callbacks (must not be NULL)
[in]channelsArray of opaque channel handles (must not be NULL)
[in]channel_countNumber of channels in the array
Returns
SAPI_STATUS_OK on success
SAPI_STATUS_INVALID_PARAM if parameters are invalid or callbacks are NULL
Precondition
storage != NULL
config != NULL
config->backend_send != NULL
config->backend_recv != NULL
channels != NULL
channel_count >= 2 (at minimum 2 redundant channels required)
channel_count <= SAPI_VITAL_CHANNEL_MAX_CHANNELS
Postcondition
On success, storage contains initialized vital channel state
Safety:
No dynamic memory allocation; caller provides storage. This function performs no I/O operations; all channels must be pre-configured and operational before calling this function.

sapi_status_t sapi_vital_channel_send ( sapi_vital_channel_t *  handle,
const void *  data,
size_t  data_size 
)

Send data via vital channel (broadcast to all redundant channels)

Broadcasts the message to all redundant channels. All channels must complete successfully for the send to succeed (atomic semantics).

If any channel fails, the entire send fails and no data is transmitted to any channel (all-or-nothing).

Parameters
[in]handleVital channel handle (must not be NULL)
[in]dataData to send (must not be NULL)
[in]data_sizeSize of data in bytes
Returns
SAPI_STATUS_OK if all channels accepted the send
SAPI_STATUS_INVALID_PARAM if handle or data is NULL
SAPI_STATUS_TIMEOUT if any channel times out
SAPI_STATUS_HARDWARE_FAULT if redundancy is compromised
Precondition
handle != NULL
data != NULL
data_size > 0
Safety:
Atomic: either all channels succeed or none do. Partial sends are not possible, preventing inconsistent system state.

)

Receive data via vital channel (voting-based reception)

Receives from all redundant channels and applies voting logic to determine the canonical result. Automatically detects disagreements and triggers safe-state on voting failure.

Parameters
[in]handleVital channel handle (must not be NULL)
[out]dataBuffer to receive data (must not be NULL)
[in]data_sizeSize of data buffer
[out]resultVoting result status (can be NULL)
[out]bytes_receivedNumber of bytes actually received (can be NULL)
Returns
SAPI_STATUS_OK if voting succeeded and data is valid
SAPI_STATUS_INVALID_PARAM if handle or data is NULL
SAPI_STATUS_TIMEOUT if voting timeout expires
SAPI_STATUS_HARDWARE_FAULT if channels disagree (triggers safe-state)
Precondition
handle != NULL
data != NULL
data_size > 0
Postcondition
On disagreement, safe-state is automatically triggered via sapi_safestate_enter() with SAPI_SAFESTATE_LEVEL_SAFE
Safety:
Voting is atomic: all channels must complete or timeout. Disagreement triggers safe-state to prevent corrupted data propagation.
